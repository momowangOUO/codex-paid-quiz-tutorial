What You Build

不是“按钮式建站”，而是一条完整收款链路

教程会把一个低价一次性解锁产品拆成可验收的小任务。你会知道每一步该让 Codex 做什么、 怎么检查、哪些东西不能放到前端。

01

先做能跑通的产品

首页、测验、免费导言、付费墙、完整报告。第一版先证明流程成立，不急着堆功能。

02

让后端掌握付款状态

用户不能靠 URL 参数假解锁。只有 Paddle webhook 确认后，后端才发放 access token。

03

部署后再接 Paddle

先用 Zeabur 拿 HTTPS 域名，再去 Paddle 做网站验证、价格、webhook 和 checkout。

01

产品流程怎么拆

先画出首页、答题页、免费报告、付款页、完整报告的最短路径。

 02

让 Codex 从 0 建站

把网站拆成小轮次：先流程、再后端、再 mock、最后接 Paddle。

 03

上传到 GitHub

整理仓库、保护密钥、推送代码，让 Zeabur 能从 GitHub 自动部署。

 04

部署到 Zeabur

设置 build、start、PORT、volume 和环境变量，先拿到 Paddle 能验证的域名。

 05

接 Paddle 收费

配置 product、price、default payment link、webhook，并确认付款后自动解锁。

 06

提示词模板

复制就能用的 Codex 指令，用来建站、接金流、修部署、查 secret。

 07

上线检查清单

上线前检查产品、付款、解锁、安全、手机体验和真实环境变量。

Payment Flow

付款后自动解锁，不靠兑换码

真实付款流程的关键，是让前端只负责展示，后端负责订单状态，Paddle 负责收款并通过 webhook 通知结果。
