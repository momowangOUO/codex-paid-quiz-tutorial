# 07. 라이브 체크리스트 시작

![출시 체크리스트 챕터 아트](../../assets/chapters/chapter-07-launch.webp)
**[이 장의 핵심] 온라인에 접속하기 전에 제품 프로세스, GitHub, Zeabur, Paddle, 환경 변수 및 결제 보안을 하나씩 확인하십시오. **

온라인에 접속하기 전에 "페이지가 아름다운지 아닌지"만 보지 마십시오. 유료사이트에서 가장 중요한 점은 사용자가 결제를 완료하고 결제 후 물건을 받을 수 있으며, 결제하지 않은 사람은 우회할 수 없다는 점이다.

이 목록을 하나씩 살펴보세요.

> 💡 **왜 이러는 걸까요#  **
> 유료 웹사이트의 위험성은 페이지의 시각적인 모습에만 국한되지 않습니다. 주문, 웹훅, 키, 잠금해제 권한 중 하나라도 오류가 있는 경우, 사용자는 '결제했지만 볼 수 없음' 또는 '결제하지 않았지만 볼 수 없음' 문제가 발생할 수 있습니다.

## 1. 기본 기능

**[이 섹션의 핵심] 먼저 사용자가 홈 페이지에서 보고서 페이지로 이동할 수 있는지 확인합니다. **

- [ ] 홈페이지를 열 수 있습니다.
- [ ] 사용자가 퀴즈를 시작할 수 있습니다.
- [ ] 사용자는 모든 질문을 완료할 수 있습니다.
- [ ] 응답 후 `reportId`를 생성합니다.
- [ ] 보고서의 무료 소개 버전이 표시될 수 있습니다.
- [ ] 미납 시 전체 보고서가 잠깁니다.
- [ ] 결제 버튼을 누르면 결제 세션을 생성할 수 있습니다.
- [ ] 결제 성공 후 자동으로 잠금이 해제될 수 있습니다.
- [ ] 페이지를 새로 고친 후에도 잠금 해제된 보고서를 열 수 있습니다.
- [ ] 브라우저를 변경하거나 토큰 없이는 다른 사람의 전체 보고서를 볼 수 없습니다.

## 2. Codex 배송검사

**【이 섹션의 핵심】Codex가 기본 검사를 실행하고 오류 없이 온라인 상태가 되도록 합니다. **

Codex를 실행해 보세요:```bash
npm run typecheck
npm run build
```

실패하면 열심히 온라인에 접속하지 마십시오. 오류를 Codex에 다시 게시하세요.

```text
이것은 npm 실행 빌드의 버그입니다. 이를 해결하도록 도와주세요.
[게시 오류]
```

## 3. 공문서 조사

**【이 섹션의 핵심】사용자가 볼 수 있는 파일에 비밀이 없는지 확인하세요. **

사용자는 다음 파일을 볼 수 있습니다.

```text
공개/*
거리/*
프론트엔드 패키지 js/css
```

다음이 포함되어 있지 않은지 확인하세요.

- 패들 API 키.
- 웹훅 비밀.
- 관리 토큰.
- `.env.payment.local` 콘텐츠.
- 개인 테스트 주문 정보.

Codex에 문의하여 다음 사항을 확인할 수 있습니다.

```text
API 키, 웹훅 시크릿, 어드민 토큰이 유출되지 않았는지 확인하기 위해 퍼블릭, dist, 프론트엔드 소스코드를 스캔해주세요.
```

## 4. GitHub 확인

**【이 섹션의 핵심】Zeabur가 GitHub에서 최신 보안 버전을 다운로드할 것인지 확인하세요. **

Zeabur는 GitHub에서 코드를 가져오므로 배포하기 전에 저장소 상태를 확인하세요.

- [ ] GitHub 저장소가 생성되었습니다.
- [ ] 이 시스템의 최신 수정 사항이 커밋되었습니다.
- [ ] 이 기계의 최신 수정 사항이 푸시되었습니다.
- [ ] 최신 README 및 코드는 GitHub 페이지에서 확인하실 수 있습니다.
- [ ] .env가 업로드되지 않았습니다.
- [ ] .env.pay.local이 업로드되지 않았습니다.
- [ ] Paddle API 키, 웹훅 비밀, 관리자 토큰이 창고에 표시되지 않습니다.
- [ ] GitHub 창고 주소를 Zeabur에 복사하여 사용할 수 있습니다.

## 5. 지아부르 검사

**【이 섹션의 핵심】온라인 서비스를 시작하고 액세스할 수 있으며 결제 정보를 저장할 수 있는지 확인하세요. **

공개적으로 액세스 가능한 HTTPS 도메인 이름을 얻으려면 먼저 이 작업을 수행하십시오. Paddle의 웹사이트 확인, 기본 결제 링크 및 웹훅에는 모두 이 도메인 이름이 필요합니다.

- [ ] GitHub 저장소가 최신 코드입니다.
- [ ] Zeabur는 올바른 저장소와 분기를 연결합니다.
- [ ] 빌드 명령은 `npm run build`입니다.
- [ ] 시작 명령은 `npm run start`입니다.
- [ ] 서비스 수신 `process.env.PORT`.
- [ ] 호스트는 `0.0.0.0`를 사용합니다.
- [ ] `/api/health`에 액세스할 수 있습니다.
- [ ] `/monetization.json`에 액세스할 수 있습니다.
- [ ] `/data` 볼륨 세트.
- [ ] `PAYMENT_STORE_FILE=/data/payment-store.json`.
- [ ] `https://你的项目.zeabur.app`와 같은 Zeabur HTTPS 도메인 이름을 얻었습니다.

## 6. 패들 점검

**【이 섹션의 핵심】Paddle 계정, 도메인 이름, 제품, 가격 및 웹훅이 모두 준비되었는지 확인하세요. **

Zeabur 웹사이트가 열리면 Paddle을 하세요. 도메인 이름이 없을 때 결제를 강요하지 마세요.

- [ ] 패들 온보딩이 완료되었습니다.
- [ ] 웹사이트 도메인 이름이 확인되었습니다.
- [ ] 가격 페이지는 Zeabur 도메인 이름 아래의 공개 페이지를 작성합니다.
- [ ] 서비스 약관 / 개인 정보 보호 정책 / 환불 정책은 모두 경로가 포함된 URL을 사용합니다.
- [ ] 기본 결제 링크는 확인된 도메인 이름으로 설정됩니다.
- [ ] 제품이 생성되었습니다.
- [ ] 일회성 가격이 설정되었습니다.
- [ ] CNY 가격 ID가 Zeabur 환경 변수에 채워집니다.
- [ ] USD 가격 ID가 Zeabur 환경 변수에 채워집니다.
- [ ] API 키는 올바른 환경(샌드박스 또는 라이브)입니다.
- [ ] 웹훅 대상은 `https://你的域名/api/webhooks/paddle`를 가리킵니다.
- [ ] Webhook 비밀이 Zeabur 변수에 채워집니다.
- [ ] `transaction.completed` 이벤트가 선택되었습니다.
- [ ] 샌드박스 결제로 인해 웹훅이 실행될 수 있습니다.

## 7. 환경변수 확인

**【이 섹션의 핵심】배포 플랫폼의 변수가 완전하고 환경이 일관성이 있는지 확인합니다. **

최소한 Zeabur 변수. 처음으로 도메인 이름을 얻으려는 경우 Paddle 관련 변수를 비워 두거나 자리 표시자 값을 사용할 수 있습니다. Paddle이 제품, 가격, 웹훅을 작성하기 전에 이를 기다립니다.```bash
PAYMENT_SERVER_HOST=0.0.0.0
PAYMENT_STORE_FILE=/data/payment-store.json
PUBLIC_BASE_URL=https://你的域名
CORS_ORIGIN=https://你的域名
PADDLE_ENVIRONMENT=sandbox
PADDLE_API_KEY=...
PADDLE_CNY_PRICE_ID=pri_...
PADDLE_USD_PRICE_ID=pri_...
PADDLE_WEBHOOK_SECRET=...
PADDLE_ALLOW_UNSIGNED_WEBHOOKS=false
```

라이브로 전환할 때 모든 샌드박스를 라이브로 교체하세요. 그것들을 섞지 마십시오.

## 8. 유료보안점검

**【이 섹션의 핵심】실제 결제가 성공한 경우에만 잠금이 해제된다는 점을 확인하세요. **

최소한 다음 시나리오를 테스트하십시오.

- [ ] URL과 `# paid=true`는 잠금 해제되지 않습니다.
- [ ] 세션 ID를 임의로 변경하면 잠금이 해제되지 않습니다.
- [ ] 오류 웹훅 비밀이 잠금 해제되지 않습니다.
- [ ] 중복된 웹훅이 여러 번 발행되지 않습니다.
- [ ] `transaction.payment_failed`는 잠금 해제되지 않습니다.
- [ ] `transaction.completed`가 잠금 해제됩니다.
- [ ] 동일한 주문에 대해 다른 보고서 ID를 잠금 해제할 수 없습니다.

## 9. 실제 사용자 경험 확인

**【이 섹션의 핵심】휴대폰과 컴퓨터를 사용하여 전체 과정을 한 번만 진행하세요. **

휴대폰에서 한 번, 컴퓨터에서 한 번 실행하세요.

- [ ] 홈페이지 카피가 이해가 됩니다.
- [ ] 시작버튼이 눈에 띕니다.
- [ ] 답변 페이지에서 계속 슬라이드할 필요가 없습니다.
- [ ] 전문적인 느낌의 무료 보고서입니다.
- [ ] 결제버튼이 선명해졌습니다.
- [ ] 결제 후 대기 프롬프트가 있습니다.
- [ ] 잠금 해제 후 전체 보고서 레이아웃이 안정적입니다.
- [ ] 보고서 저장이 실패하거나 잘리지 않습니다.

## 10. 온라인 접속 전 시험장 입구를 닫아주세요

**【이 섹션의 핵심】공식 출시 전에 모든 테스트 바로가기를 닫습니다. **

이러한 테스트 기능이 있는 경우 라이브로 전환하기 전에 해당 기능을 끄십시오.

- [ ] 버튼을 누르면 결과 페이지로 바로 이동합니다.
- [ ] 0위안 테스트 잠금 해제 버튼.
- [ ] 모의결제 버튼.
- [ ] 관리자 구성 항목.
- [ ] 모든 디버그 패널.

일부러 보관하고 싶다면 적어도 일반 사용자가 볼 수 없는 곳에 보관하세요.

## 11. 접속 후 첫날 시청해야 할 것

**【이 섹션의 핵심】 출시 첫날에는 결제 링크 및 잠금 해제 실패에 중점을 둡니다. **

온라인 접속 후 방문 횟수만 보지 마세요. 하이라이트:

- 퀴즈를 시작한 사람은 몇 명입니까?
- 퀴즈를 완료한 사람은 몇 명입니까?
- 결제를 클릭한 사람 수.
- Paddle 체크아웃이 켜져 있나요?
- 웹훅 성공률.
- 결제 성공 후 잠금해제 실패는 없나요?
- 사용자가 '유료인데 볼 수 없습니다'라고 신고한 적이 있나요?
저가형 제품은 결제링크 오류가 가장 두렵습니다. 첫날에 더 많은 로그를 읽어보세요.

## 한 문장으로 합격

**【이 섹션의 핵심】알 수 없는 사용자는 테스트를 완료하고 비용을 지불하며 자동으로 전체 보고서를 볼 수 있는 경우에만 온라인에서 성공한 것으로 간주될 수 있습니다. **

안정적으로 할 수 있을 때:

```text
알 수 없는 사용자가 웹사이트 열기 -> 퀴즈 완료 -> 결제 -> 자동으로 전체 보고서 보기
```

그 때는 정말 온라인이죠.
