# 01. 제품 흐름 나누기

**목표: 코드를 쓰기 전에 사용자가 어떤 화면을 지나 결제와 잠금 해제를 하게 되는지 정합니다.**

가장 짧은 흐름은 다음과 같습니다.

```text
랜딩 페이지 -> 퀴즈 -> 무료 인트로 리포트 -> 결제 -> 전체 리포트 -> 저장 또는 재방문
```

첫 버전에서는 로그인, 구독, 쿠폰, 관리자 화면을 넣지 마세요. 먼저 한 명의 사용자가 답변하고, 한 번 결제하고, 정확한 리포트를 열 수 있는지 확인합니다.

## 화면별 역할

| 화면 | 사용자가 보는 것 | 역할 | 백엔드 필요 여부 |
| --- | --- | --- | --- |
| 랜딩 | 가치 설명과 시작 버튼 | 퀴즈 시작 | 보통 불필요 |
| 퀴즈 | 질문, 선택지, 진행률 | 답변 수집 | 보통 불필요 |
| 무료 인트로 | 일부 분석 | 신뢰 형성 | reportId 필요 |
| 결제벽 | 가격, 결제 버튼, 대기 상태 | payment session 생성 | 필요 |
| 전체 리포트 | 레이더, 심리 프로필, 방향 | 유료 가치 전달 | access token 필요 |

## 무료 리포트의 범위

무료 리포트는 빈 광고 페이지가 아니어야 합니다. 핵심 동기, 행동 경향, 자기 인식과 실제 표현의 차이, 전체 리포트에서 다룰 분석 축을 보여줄 수 있습니다. 다만 전체 직업명, 전체 경로, 저장용 리포트, 모든 매칭 로직은 숨깁니다.

## 핵심 데이터

### reportId

`reportId` 는 하나의 퀴즈 결과를 나타내는 번호입니다. 답변, 주문, 잠금 해제, 재방문이 모두 같은 결과를 가리켜야 합니다.

### payment session

`payment_session` 은 한 번의 결제 시도입니다. 사용자는 결제를 닫거나 실패 후 재시도할 수 있으므로 상태는 프론트엔드가 아니라 백엔드에 저장해야 합니다.

### access token

`accessToken` 은 전체 리포트를 여는 열쇠입니다. 어떤 reportId 가 한 번 결제되었다고 해서 모든 사람이 볼 수 있게 만들면 안 됩니다.

## Codex 프롬프트

```text
일회성 결제로 리포트를 잠금 해제하는 퀴즈 사이트를 만들고 싶습니다.

사용자 흐름: 랜딩 페이지 -> 퀴즈 -> 무료 인트로 리포트 -> 결제 -> 전체 리포트.

첫 버전은 로그인, 구독, 쿠폰 없이 진행합니다.

다음을 설계해 주세요:
1. 프론트엔드 화면 상태
2. reportId 생성과 저장
3. payment session 데이터 구조
4. access token 잠금 해제 로직
5. 로컬 mock 결제 흐름

먼저 파일 계획을 출력한 뒤 최소 버전을 구현해 주세요.
```
