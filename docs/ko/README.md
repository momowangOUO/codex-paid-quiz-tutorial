이 문서는 전체 Markdown 튜토리얼 목차입니다. 가능한 한 순서대로 읽는 것을 권장합니다. 뒤쪽의 결제, 배포, 출시 전 점검은 앞에서 만든 제품 흐름, 저장소 구조, 환경 변수 설계에 의존합니다.

## 장

| 순서 | 장 | 완료할 내용 |
| --- | --- | --- |
| 1 | [제품 흐름 분해하기](01-product-flow.md) | 유료 사이트를 사용자 경로, 페이지, 상태, 데이터, 잠금 해제 조건으로 나눕니다. |
| 2 | [Codex로 0부터 구축하기](02-codex-build-workflow.md) | 명확한 프롬프트로 Codex가 프로젝트 뼈대를 만들게 하고 작은 단위로 수정합니다. |
| 3 | [GitHub에 업로드하기](03-upload-to-github.md) | 저장소를 만들고 커밋하며 비밀 값과 로컬 임시 파일을 제외합니다. |
| 4 | [Zeabur에 배포하기](04-zeabur-deployment.md) | 빌드 명령, 시작 명령, 환경 변수, 공개 도메인을 설정합니다. |
| 5 | [Paddle 결제와 자동 잠금 해제 연결하기](05-payment-unlock.md) | Paddle Checkout, Webhook, 결제 세션 조회, 유료 리포트 잠금 해제를 연결합니다. |
| 6 | [복사 가능한 Codex 프롬프트](06-prompt-templates.md) | 제품 설계, 개발, 디버깅, 보안 점검, 출시 전 리뷰에 쓸 수 있는 프롬프트를 활용합니다. |
| 7 | [출시 전 체크리스트](07-launch-checklist.md) | 보안, 결제, 배포, 콘텐츠, 롤백, 사용자 경험을 확인합니다. |

## 추천 읽기 순서

1. 먼저 1장을 읽고 제품이 1회 결제 잠금 해제 모델에 맞는지 확인합니다.
2. 2장부터 4장까지는 실제로 만들면서 진행합니다.
3. 5장에서는 Webhook과 비밀 값 처리 부분을 건너뛰지 마세요.
4. 6장은 설계, 구현, 수정, 리뷰가 필요할 때 언제든 사용할 수 있습니다.
5. 7장은 실제 출시 전 체크리스트로 사용하세요.
