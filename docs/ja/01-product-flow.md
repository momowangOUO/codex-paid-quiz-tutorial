# 01. プロダクトの流れを分解する

**目的：コードを書く前に、ユーザーがどの画面を通り、どの時点で決済と解放が必要になるかを決めます。**

最短の流れは次の形です。

```text
トップページ -> 診断 -> 無料の導入レポート -> 決済 -> 完全版レポート -> 保存または再閲覧
```

最初からログイン、サブスク、クーポン、管理画面を入れないでください。まず「回答して、一回だけ支払い、正しいレポートが開く」ことを証明します。

## 画面ごとの役割

| 画面 | ユーザーが見るもの | 役割 | バックエンド |
| --- | --- | --- | --- |
| トップ | 価値説明と開始ボタン | 診断を始める | 通常不要 |
| 診断 | 質問、選択肢、進捗 | 回答を集める | 通常不要 |
| 無料導入 | 一部の分析 | 信頼を作る | reportId が必要 |
| ペイウォール | 価格、決済ボタン、待機状態 | payment session を作る | 必要 |
| 完全版 | レーダー、心理プロファイル、方向性 | 有料価値を届ける | access token が必要 |

## 無料版に出す内容

無料版は空の宣伝ページではありません。核心的な動機、行動傾向、自己認識とのずれ、完全版で扱う分析軸を見せます。ただし、完全な職業名、全ルート、保存用レポート、全てのマッチングロジックは出しません。

## 重要なデータ

### reportId

`reportId` は一つの診断結果を表す番号です。回答、注文、解放、再訪問を同じ結果に結びつけます。

### payment session

`payment_session` は一回の決済試行です。ユーザーは決済ページを閉じたり、失敗後に再試行したりします。そのため状態はフロントエンドだけに置かず、バックエンドに保存します。

### access token

`accessToken` は完全版レポートを開く鍵です。reportId が一度支払われたからといって、全員に見せてはいけません。

## Codex に渡すプロンプト

```text
一回払いでレポートを解放する診断サイトを作りたいです。

ユーザーの流れ：トップページ -> 診断 -> 無料導入レポート -> 決済 -> 完全版レポート。

初版ではログイン、サブスク、クーポンは不要です。

以下を設計してください：
1. フロントエンドの画面状態
2. reportId の生成と保存
3. payment session のデータ構造
4. access token による解放ロジック
5. ローカル用 mock 決済フロー

まずファイル計画を出し、その後に最小版を実装してください。
```
