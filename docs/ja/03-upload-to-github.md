# 03. まず GitHub にアップロードし、Zeabur にデプロイする準備をします

![GitHub アップロード チャプター アート](../../assets/chapters/chapter-03-github.webp)
この章はゼアブルの前に置かれます。

**[この章の核心] Zeabur は通常、デプロイメントのために GitHub からコードをプルするため、最初にローカル プロジェクトを GitHub リポジトリにアップロードします。 **

3 つの関係は次のように理解できます。

```text
コンピューター: コードを書いたりテストしたりする場所
GitHub: コードを保存するためのクラウド ウェアハウス
Zeabur: GitHub からコードを取得して Web サイトに実行します
```

> 💡 **なぜこれを行うのですか#  **
> Zeabur はコンピュータのデスクトップからファイルを直接読み取りません。通常、GitHub リポジトリに接続し、リポジトリを更新するたびに再デプロイされます。ここで GitHub は「プロジェクト転送ステーション」のようなもので、Zeabur は「転送ステーションでプロジェクトを開始して実行する人」のようなものです。

### ステップ 1: GitHub アカウントを既に持っていることを確認する

**【このステップの核心】プロジェクトコードを保存するにはGitHubアカウントが必要です。 **

次に、具体的な実行手順を示します。

1. GitHub 公式 Web サイトを開きます。
2. すでにログインしている場合は、次のステップに進みます。
3. まだアカウントをお持ちでない場合は、アカウントを登録します。
4. GitHub ユーザー名を覚えておいてください。これは後でウェアハウスのアドレスに使用されます。

> 💡 **なぜこれを行うのですか#  **
> GitHub は、プログラマーが一般的に使用するコード リポジトリ プラットフォームです。ウェアハウスは、すべての重要な変更を保存する「プロジェクト専用のクラウド フォルダー」として理解できます。

### ステップ 2: GitHub に新しいリポジトリを作成する

**【このステップの核心】Web サイトのコードを保存するためのリポジトリを作成します。 **

次に、具体的な実行手順を示します。

1. GitHub を開きます。
2. 右上隅の「`+`」をクリックします。
3. `New repository` を選択します。
4. `Repository name` にプロジェクト名を入力します。例:

```text
有料クイズサイト
```

5. `Description` を最初に書き込むことができます。

```text
Codexで構築された有料クイズサイト。
```

6. 可視性は `Public` または `Private` を選択できます。
7. ローカル プロジェクトがまだない場合は、`Add a README file` を確認できます。
8. すでにローカル プロジェクトがある場合は、ローカル ファイルとの競合を避けるために、最初に README を確認しないことをお勧めします。
9. 「`Create repository`」をクリックします。

> 💡 **なぜこれを行うのですか#  **
> リポとはリポジトリの略で倉庫という意味です。 1 つのリポジトリは 1 つのプロジェクトに対応します。 Web サイトのコード、ドキュメント、展開構成はすべてこのウェアハウスに配置されます。

### ステップ 3: シークレットをアップロードしないことを最初に確認します

**[このステップの核心] 初めてアップロードする前に、キー、注文、およびバックグラウンド データが GitHub にプッシュされないことを確認してください。 **

このコンテンツをアップロードしないでください:

- `.env`
-`.env.payment.local`
-パドルAPIキー
- パドル Webhook シークレット
-管理者トークン
- 実際の注文情報
- 決済プラットフォームのバックエンド画面
-`node_modules`
-`dist`
- ログファイル

プロジェクトのルート ディレクトリには `.gitignore` が必要です。少なくとも以下を含めることをお勧めします。

```text
.env
.env.*
*.local
ノードモジュール
距離
.logs
tmp-*
*.log
```Codex にチェックを依頼できます。

```text
このプロジェクトが GitHub へのアップロードに適しているかどうかを確認してください。

要件:
1. .gitignore は、.env、.env.*、*.local、node_modules、dist、ログ、および一時ファイルを除外する必要があります。
2. プロジェクトをスキャンして、Paddle API キー、Webhook シークレット、または管理者トークンがないことを確認します。
3. シークレットを見つけた場合は、ファイル パスを教えて、対応するキーを取り消すか置き換えるよう提案してください。
4. 私のビジネスコードを削除しないでください。
```

> 💡 **なぜこれを行うのですか#  **
> GitHub はコードの保存には適していますが、キーの保存には適していません。 API キーはバックエンド キーのようなものです。パブリック リポジトリに入るか履歴をコミットすると、公開されたものとみなされ、後で再生成する必要があります。

### ステップ 4: Git がこのマシンにインストールされていることを確認する

**[このステップの核心] Git は、ローカル プロジェクトを GitHub に送信するためのツールです。 **

ターミナルで実行します。```bash
git --version
```

次のようなものが表示された場合:

```text
git バージョン 2.x.x
```

説明文がインストールされました。

`git` が見つからないというメッセージが表示された場合は、続行する前に Git をインストールしてください。

> 💡 **なぜこれを行うのですか#  **
> Git は「バージョン記録ツール」です。どのファイルを変更したかを記録し、ネイティブ コードを GitHub にプッシュすることもできます。 GitHub はクラウド プラットフォームであり、Git はローカルで GitHub と通信するために使用するツールです。

### ステップ 5: プロジェクトのルート ディレクトリで Git を初期化する

**【このステップの核心】プロジェクトがまだ Git ウェアハウスではない場合は、最初にプロジェクトを Git ウェアハウスにします。 **

プロジェクトのルート ディレクトリで実行します。```bash
git status
```

ファイルのステータスが表示された場合、それはすでに Git リポジトリであることを意味します。

次のようなものが表示された場合:

```text
致命的: git リポジトリではありません
```

実行するだけです:```bash
git init
```

次に、以下を実行します。```bash
git status
```

> 💡 **なぜこれを行うのですか#  **
> `git init` はプロジェクトフォルダに「変更ログ」を置くようなものです。この瞬間から、Git はこのプロジェクトを追跡することを認識します。

### ステップ 6: ファイルを最初のコミットに追加する

**【このステップの核心】現在のプロジェクトのステータスをコミットとして保存します。 **

埋め込む：```bash
git add .
git commit -m "Initial paid quiz website"
```Git で名前と電子メール アドレスの設定を求められた場合は、次のようなプロンプトに従います。```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

次に、再度実行します。```bash
git commit -m "Initial paid quiz website"
```

> 💡 **なぜこれを行うのですか#  **
> コミットは「アーカイブ」として理解できます。ファイルを GitHub に大まかにダンプするのではなく、特定のバージョンをローカルに保存し、そのバージョンをプッシュします。

### ステップ 7: GitHub リモート リポジトリに接続する

**[このステップの核心] ローカル Git に指示します: このプロジェクトをどの GitHub リポジトリにプッシュするかを指定します。 **

GitHub がウェアハウスを構築すると、通常は次のようなアドレスが提供されます。

```text
https://github.com/あなたのユーザー名/あなたのウェアハウス名.git
```

ターミナルで実行します。```bash
git branch -M main
git remote add origin https://github.com/你的用户名/你的仓库名.git
```

`origin already exists` というプロンプトが表示される場合は、リモート アドレスがすでに存在することを意味します。以下を表示できます。```bash
git remote -v
```

アドレスが間違っている場合は、次のように変更できます。```bash
git remote set-url origin https://github.com/你的用户名/你的仓库名.git
```

> 💡 **なぜこれを行うのですか#  **
> `origin` は、リモート ウェアハウスのローカル Git のニックネームです。 Git に次のように伝えます。今後、オリジンへのプッシュというときは、この GitHub リポジトリへのプッシュを意味します。

### ステップ 8: GitHub にプッシュする

**【このステップの核心】ローカルコミットをGitHubにアップロードします。 **

埋め込む：```bash
git push -u origin main
```

初めてプッシュするとき、GitHub はログインまたは承認を求める場合があります。

プッシュが成功した後:

1. GitHub リポジトリ ページを開きます。
2. Web ページを更新します。
3. プロジェクト ファイルが表示されることを確認します。
4. READMEが正常に表示されることを確認します。
5. 倉庫に `.env` と `.env.payment.local` が表示されないことを確認します。

> 💡 **なぜこれを行うのですか#  **
> `git push` は「ローカルアーカイブをクラウドウェアハウスにアップロード」です。 Zeabur は、コンピューター上のフォルダーではなく、GitHub 上のコードを読み取ります。

### ステップ 9: 変更を加えるたびに 3 つのステップを使用して更新します。

**[このステップの核心] 今後 Web サイトを変更した後、追加、コミット、プッシュの 3 つのステップを使用して、Web サイトを GitHub に同期します。 **

変更するたびに実行します。```bash
git status
git add .
git commit -m "Describe what changed"
git push
```

送信メッセージは、次のようにより具体的にすることもできます。```bash
git commit -m "Add Paddle webhook unlock flow"
```

または：```bash
git commit -m "Improve unpaid report preview"
```

> 💡 **なぜこれを行うのですか#  **
> Zeabur は通常、GitHub リポジトリの変更を監視します。新しいコミットをプッシュすると、Zeabur はオンライン サービスを再デプロイする必要があることを認識します。

### ステップ 10: アップロードして Zeabur を入力します

**【このステップの核心】GitHub ウェアハウスに既にコードがあることを確認し、Zeabur に移動してデプロイメント用にこのウェアハウスを選択します。 **

次の章に進む前に、次のことを確認してください。

1. GitHub ウェアハウスのページを開くことができます。
2. READMEを表示できます。
3. メインコードファイルがアップロードされました。
4. `.env`、`.local`、APIキーはアップロードされません。
5. 倉庫の住所がわかっているとします。例:

```text
https://github.com/あなたのユーザー名/paid-quiz-site
```

この倉庫は次の章で Zeabur で選択されます。

> 💡 **なぜこれを行うのですか#  **
> Zeabur のデプロイメントエントリは通常「GitHub リポジトリを選択」です。リポジトリにコードがまだない場合、Zeabur にはデプロイ先がありません。

### この章の完了基準

**【この章の核心】GitHub 上でプロジェクト全体を表示し、キーが漏洩していないことを確認できる必要があります。 **

完了後、項目ごとに確認してください。

1. GitHub リポジトリが作成されました。
2. ネイティブ プロジェクトはすでに `git commit` です。
3. ネイティブ プロジェクトは `git push` です。
4. プロジェクト ファイルは GitHub ページで確認できます。
5. `.env` はアップロードされていません。
6. `.env.payment.local` はアップロードされません。
7. API キー、Webhook シークレット、および管理トークンがウェアハウスに表示されません。
8. Zeabur に移動し、デプロイメント用にこのリポジトリを選択する準備が整いました。
