# 01. 产品与流程设计

本章先把产品想清楚。不要一开始就接支付，先做出用户愿意完成的体验。

## 最小可卖版本

- 免费入口：用户可以完成测验，并看到一份有专业感的导言版结果。
- 付费内容：完整报告、职业方向、行动路线与可保存报告。
- 价格策略：先用低价一次性解锁，降低第一次付费阻力。
- 解锁方式：付款成功后由后端确认，自动解锁页面。

## 推荐流程

1. 首页说明测验价值，但不要过早强调收费。
2. 用户完成题目，系统生成 reportId。
3. 结果页先提供可信的免费导言。
4. 用户决定解锁，进入 Paddle Checkout。
5. Paddle webhook 通知后端，后端标记 paid。
6. 前端轮询或回到报告页后读取状态，自动显示完整报告。

## 你可以交给 Codex 的提示词

```text
请帮我设计一个可收费的测验网站流程：
- 免费完成测验
- 免费结果只显示专业导言
- 完整报告付款后解锁
- 不用兑换码
- 后端负责订单状态和访问权限
请先列出页面、API、资料模型和测试场景。
```

## 关键判断

如果产品还没有人愿意做完整测验，支付接得再漂亮也没有意义。先优化完成率，再优化付费率。
